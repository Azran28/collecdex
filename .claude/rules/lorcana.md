# Disney Lorcana (v3.21, `js/games/lorcana.js`, 4ᵉ licence)
Même logique que Riftbound (voir `riftbound.md`) ; ici seulement ce qui diffère. Choisie par Arnaud (17 oct.) parce qu'il a des cartes (session « Licences TCG »).

## Données
- **LorcanaJSON** (`lorcanajson.org/files/current/{fr,en}/allCards.json`, données des applis officielles de Ravensburger) : **noms, textes, séries, raretés en français** ; 10 Mo par langue et **pas de CORS** → `outils/ci/lorcana-cartes.mjs` en fait `data/lc-cartes.json` (**dans le dépôt**, ~1,8 Mo, 470 Ko compressé), relancé chaque lundi par `index.yml` (étape « Liste des cartes Lorcana », `changed` si le fichier change ; fichier inchangé si seule la date diffère). Le site le lit (`index()`, cache `lc1:index` relu à chaque nouvelle `APP_VERSION` ou après 3 jours).
- Format compact : `id, s, o (chapitre d'une promo), l, n, v, st (film), r, t, k (encres), co, iw, sg, wp, lo, mv, sb, x (texte, sections séparées par \n), a, img (chemin après api.lorcana.ravensburger.com/images/), f (1 normale, 2 brillante, 3 les deux), tp (n° TCGplayer), cm (n° Cardmarket), ne (nom anglais si différent), of (total imprimé), enOnly`.
- **Id = `<série>-<numéro>`** : `1-1`, `1-205` (enchantée), `3-4a` (chiots dalmatiens 4a…4e), promos par groupe imprimé (`18/P1 • FR • 2` → `p1-18` ; groupes P1…P4, C1, C2, D23, DIS, PD1, RPH, CC1), quêtes `q1-3`. Ids LorcanaJSON communs aux langues ; 92 promos seulement anglaises (`enOnly`).
- Séries : 14 chapitres (`main`, `base` = total imprimé « /204 », `isOfficial` = numéro ≤ base sans lettre), 3 quêtes, 11 groupes de promos (noms FR dans `PROMO` de l'outil). Nom affiché « Ariel - Sur des jambes humaines ». Raretés FR : Commune, Inhabituelle, Rare, Très rare, Légendaire, Épique, Enchantée, Iconique, Spéciale (clés `c u r sr l e en i p`). Termes FR : « éclat de Lore », force `¤`, volonté, encrier `⬡`, épuiser `⟳`.
- **Images** : visuels officiels **français** (`api.lorcana.ravensburger.com/images/fr/…jpg`, 1468 × 2048 ; **403 si la requête porte un en-tête Origin**, donc jamais lus directement) → `images.weserv.nl/?url=https%3A%2F%2F…` (le `https://` doit être dans l'adresse relayée, sinon 404). Les lieux y sont déjà en hauteur (sens du classeur). `friends.js` / `duel.js` acceptent ces adresses (nom de fichier `24A_…` possible : `[A-Za-z0-9]+`).
- **Visuel de chapitre** : sachet de booster TCGplayer (`PACKS_CROP`, mesuré en ouvrant l'image sur tcgplayer-cdn ; à compléter à chaque chapitre), quêtes / promos = code (« Q1 », « P1 » ; chapitres sans sachet : « Ch. 15 »).
- **Prix** : tcgcsv.com catégorie 71 → `outils/ci/prix-lorcana.mjs` (robot de mise en ligne, chaque matin) → `_site/data/lc-prix.json` `{ m, p: { <n° TCGplayer>: [normal, brillant] } }` (pas dans le dépôt, `.gitignore` ; local → celui du site en ligne). Relié par `tp` : 3 221 cartes sur 3 228 avec un numéro. Lorcast (api.lorcast.com, CORS *, anglais seulement) = autre source possible.

## Reconnaissance
- Code en **bas à gauche** « 1/204 • FR • 1 » (numéro / total, langue, chapitre ; promo « 18/P1 • FR • 2 », quête « 1/31 • FR • Q1 ») → `codesIn` : chapitre lu à la fin, confirmé par le total (`TOTALS`), sinon série devinée par le total seul (poids 0,5) ; un « 25/165 » Pokémon ne donne rien. Zones `CODE_ZONES` (texte blanc sur noir → `invert`/`otsu`), `NAME_ZONES` (nom + version au milieu : les noms FR servent aussi, comme One Piece).
- Vérification par l'image : `data/lc-index` (3 554 cartes, `LC_INDEX_V`), visuels français = même carte que la photo ; `IMG_SURE = 30`.
- **Cadrage (v3.23, dessins d'Arnaud `_tests-scanner/lorcana/14.webp` = page 13 et `16.webp` = carte 15, traits jaunes)** : les visuels Ravensburger sont **rognés plus serré que la carte** (bordure noire presque coupée) → les coins par l'image tombaient dans la bordure, et l'accroche sur le bord le plus net (`edgeCrop` / `snapQuad`, Riftbound) prenait le cadre intérieur (bordure noire = pochette noire). Maintenant `outerQuad` : coins par l'image agrandis de `OUTER` (−5,2 %…106,2 % en largeur, −5,1 %…107,1 % en hauteur, mesuré sur les 10 cartes dessinées, ±1,5 %), `cropQuad` (coins ramenés au bord si la carte dépasse de < 6 %) ; en classeur, photo prise sur les alentours (`context`, `ctxQuad` agrandi, aussi pour le recalage de la grille). Pire coin : 5–6 % → 0,8–1,9 % de la diagonale. Pages 4, 5, 6, 13 : 36/36 sûres.
- **Inserts « puzzle » (v3.24, Arnaud : « on les drop dans les boosters »)** : grande illustration en 9 morceaux (4 aux chapitres 1–2), sans numéro ni texte, absents de LorcanaJSON → `lorcana-cartes.mjs › puzzles` les prend chez TCGplayer (tcgcsv 71, « … Puzzle Insert (Top Left) », sans « Set of 9 » ni « Complete ») : séries `PZ<chapitre>` / `PZ<chapitre>B` (2 versions aux chapitres 7 et 8), groupe « Inserts puzzle », cartes `pz6-1`…, nom « Insert puzzle - La Mer Azurite, pièce 5 », rareté et type `pz`, `tp` = produit TCGplayer (prix par `lc-prix.json`). **Positions de TCGplayer parfois fausses → pièces numérotées 1 à 9 sans position.** Images copiées dans `data/lc-puzzles/<produit>.jpg` (le relais refuse TCGplayer ; la comparaison doit lire l'image) ; une image déjà là n'est jamais retéléchargée → **photos TCGplayer fausses ou floues remplacées à la main** par des découpes de la page 11 d'Arnaud (706232 = pièce du centre, doublon de la 2 chez TCGplayer ; 706231, 706234). Chapitre sans photo encore (Hyperia City) : ajouté un lundi suivant. 98 pièces, 12 séries, +3,3 Mo. `normCard` : image locale = `new URL(img, document.baseURI)` (l'outil du robot a `<base href="../">`). Index refait : 3 652 cartes (`LC_INDEX_V = 2`). **Piège de test** : le cache d'empreintes du navigateur (IndexedDB `collecdex-vis`, clé = adresse) garde l'ancienne image si on la remplace sous la même adresse → le vider avant de mesurer.
- Page 11 (7 pièces de La Mer Azurite + 2 dos) : **7/7 pièces sûres, 2 dos ignorés** (avant les corrections : 4 sûres, dos lus comme cartes). Secours `netRescue` (réseau de neurones seul quand les points communs ne trouvent rien : pièces presque sans détails ; proposée si ≥ 0,93 avec 0,1 d'avance, sûre seulement pour une pièce de puzzle ≥ 0,97 avec 0,15 d'avance). En classeur, une case qui ressemble au dos Lorcana est lue quand même (comme One Piece), « dos » seulement si rien n'est reconnu. Pages 4, 5, 6, 13 inchangées (36/36 sûres).
- **Vraies photos d'Arnaud (v3.22)** : cartes seules 7 / 8 (Jasmine 6-84, en pochette et en main), 9 (Tadashi 155 holo, pochette noire), 10 (Présidente 17) : 4/4 justes et sûres en mode Lorcana (5–17 s), aussi en « Toutes » et depuis le mode Pokémon ; pages 4 (6-17…31), 5 (6-170…183, lieu couché, Roi Hubert normal + brillant), 6 (6-151…167) : **27/27 justes et sûres**, 15–18 s par page (1re page ~60 s : modèles à charger), aussi en « Toutes ». Corrigé : `textScores` / `otherGames` (mots lus, pas seulement le code : sinon Lorcana essayée en dernier, > 30 s) ; `detectGame` aussi sur la photo d'origine si la carte détourée ne dit rien ; numéro lu + image ≥ `V.SURE` = sûre même avec un jumeau au même dessin (promo 10/P2 = 6-29).
- Mesuré d'abord (visuels officiels posés de travers sur un fond) : 6/6 sûres par l'image (dont chiot 4a), lecture du code 3/3 en 0,3–4 s ; Capturer carte seule Lorcana / « Toutes » / mode Pokémon (bascule) : 3/3 ; page 3 × 3 fabriquée (L'Ascension des Floodborn 10…18) : 9/9 justes, 8 sûres, Mulan 15 « à vérifier » (même dessin réimprimé dans Fabuleux 10), série devinée.
- Mode Pokémon : `recognizer-text › OTHER` contenait déjà « lorcana », « disney » → `scan.otherGames(raw, except)` essaie d'abord la licence dont le code se lit (Riftbound, Lorcana), puis One Piece. `detectGame` : points Lorcana (code ≥ 0,9, Disney/Lorcana/Ravensburger, Storyborn/Floodborn/Dreamborn, éclat de Lore, chanson, mélomane, défi).
- **Dos / certification (v3.22, photos d'Arnaud `_tests-scanner/lorcana/1.webp` dos en pochette, `2.webp` dos en main ; `3.webp` = carte « appli » au QR code, pas un dos)** : la comparaison 24 × 33 seule (`App.lorcanaBacks`, `js/games/lorcana-backs.js`) laissait des faces à 0,58 (bordure noire commune) → `recognizer-image › lcBackScore` = modèle ≥ 0,6 ET rond doré au centre (`lcFeatures` : ≥ 25 % doré dans l'ellipse 50 % × 38,5 %), bas sombre ≥ 45 % (zone de texte claire des faces), reste sombre ≥ 35 %, couleurs vives ≤ 10 %, symétrie ≥ 0,6 ; 3 échelles × 5 décalages, symétrie autour du centre du rond lui-même, image recopiée dans un canevas ≤ 900 px (une ImageBitmap qui déborde ne se dessine pas pareil : 0,35 au lieu de 0,65). Ressemblance au modèle : ≥ 0,6, ou ≥ 0,2 avec rond ≥ 0,38 et symétrie ≥ 0,9, ou ≥ 0,3 avec rond ≥ 0,45 et symétrie ≥ 0,7 (dos en pochette d'un autre éclairage : modèle 0,25–0,46). Dos 0,65–0,87, 731 faces ≤ 0,35 (la plus proche : « Fauchage » Q3-34, sombre à lune dorée, rond 0,30). `App.recognizerParts.lcBackScore.last` = détail de la dernière mesure. `LC_BACK = 0`. Test : `tests/dos-lorcana.jpg` (dos réduit 126 × 176).
- **Brillant (holo)** : la mesure de Pokémon (`detectVariants`, grain de l'illustration) ne marche pas — Tadashi 155 holo 0,86, cartes normales 0,98–1,23 (le brillant Lorcana est un voile sur toute la carte) → « Normale » par défaut, à cocher sur la fiche.

## Ailleurs
- Import : `importer.js` › `LC_CODE` (code complet avec la langue, pour ne pas prendre « 4/102 » Pokémon), `LC_SETS` (noms EN/FR), `matchLC` (code, série + numéro, nom FR ou anglais ; enchantée si la ligne le dit) ; nom pris tel quel (`cleanName` coupe au tiret).
- Combats : `battle.fighterLC` (PV 30 + volonté × 15 (+ Résistance), « Défi » = force × 10 (+ Offensif), « Riposte » si Rempart / Résistance, Charge = 1 encre, `LC_INK` encre → type), `LEVELS_LC` (Apprenti → Légende, Premier Chapitre), `battleCards.effectOfLC` (texte FR, `isLcCard` avant One Piece car « Lieu » existe dans les deux), carte « Encre » `inkCard()` (`INK`, `img/combat/encre-lorcana.svg`, +3 dans la pioche perso par `withDon`), `AI_BAGS_LC`, `LIC.lorcana` (Grimoire, « Défis au Grand Illuminarium »), `say` (personnage, encre), `LC_NAMES` ; décor `illuminarium-lorcana.svg`, dos `dos-lorcana.svg`, CSS `.g-lorcana` (livre de contes : parchemin, violet, dorures).
- Badges : `lc-mickey`, `lc-princes` (`LC_PRINCESSES`), `lc-villains`, `lc-ench`. Icône `ink` (hexagone + goutte).
- Explorer / Objectifs : 4 licences → `.game-pick` défile sur téléphone, `sets.showPick(el)` centre la licence choisie.
- Tests : `tests/unit.js` (données FR, codes, combattant + cartes de pioche, « Toutes », import, index), `tests/pages.js` (séries, série 1, promos, combat, Capturer), `tests/combat.js` (combat Avancé Lorcana).
