# Dragon Ball Super Card Game (v3.68, `js/games/dragonball.js`, 9ᵉ licence, Bandai)
Même logique que Star Wars Unlimited (voir `starwars.md`) ; ici seulement ce qui diffère. Id de licence `dragonball`, préfixe `db`. C'est le jeu « Masters » (BT1…BT31, 2017-2026) ; **Fusion World (FB01…, 2024) est un autre jeu, pas pris en charge** (import : ligne ignorée). Arnaud a des cartes françaises de Critical Blow (BT22) : photos `_tests-scanner/01.jpg` (page BT22-083…126 + 1 dos Star Wars) et `16.jpg` (page BT22-053…079 + leader Son Goten recto + leader Son Goku et Vegeta au verso + Extra Z couchée), copies dans `_tests-scanner/dragonball/`, bonnes réponses dans `reponses.txt`. Pas encore de carte seule ni de dos.

## Données
- **Site officiel Bandai en français** : `https://www.dbs-cardgame.com/europe-fr/cartes/?search=true&category=46xxxx` (une page HTML par série, 76 pages, ~30 Mo ; **pas de CORS**) ; numéros de catégories dans les `<option value="46…">` de `…/europe-fr/cartes/`. Chaque `<li>` : `cardNumber`, `cardName`, `seriesCol`, `rarityCol` (« Rare[R] »), `typeCol` (LEADER / COMBAT / EXTRA / UNISSON, + « Z »), `colorCol` (Rouge / Bleu / Vert / Jaune / Noir / Blanc, multicolores « Rouge/Bleu »), `powerCol`, `energyCol` (« 3(●●●) »), `comboEnergyCol`, `comboPowerCol`, `characterCol`, `specialTraitCol` (Origine), `eraCol`, `skillCol` (pictogrammes `alt="Auto"` → « [Auto] », boules `yellow_ball.png` → « (J) ») ; leader : 2ᵉ bloc `<div class="cardBack">` = verso éveillé (`…_b.png`). Une carte peut être sur deux pages (promo, coffret) : gardée une fois.
- **Visuels** `https://www.dbs-cardgame.com/europe-fr/images/cartes/cardimg/BT22-083.png` (260 × 364, pas de CORS) → toujours par le relais `images.weserv.nl` (`&output=webp`). **Extra Z = cartes imprimées couchées** (le site les montre en largeur avec des marges blanches) : `&trim=20&ro=90` (marges retirées, tournées vers la droite = sens du classeur, titre à droite, photo 16).
- `outils/ci/dragonball-cartes.mjs` → `data/db-cartes.json` (**dans le dépôt**, 1,7 Mo, 7 245 cartes, 87 séries) + **`data/db-textes.json`** (2,9 Mo, textes à part, lus seulement par la fiche d'une carte : `App.games.get('dragonball').texts()`, cache `db1:textes`), chaque lundi par `index.yml` (étape « Liste des cartes Dragon Ball Super », `cartes_db`). Essais : `DB_CACHE=<dossier>` garde les pages téléchargées. Cache `db1:index`. Format : `id, s, l, n, ne (anglais, TCGplayer), t (le ba ex un), z (Z), c (couleurs r b v j n w), p, co (« X » possible), ce / cp (combo), ch (personnage), tr (origine), er (ère), r, img (si l'image n'a pas le nom du numéro), bk (verso), bn / bp (nom et puissance du verso), b (carte d'origine d'une version), tp (produit TCGplayer), vf (« hn » / « h » / « n »)` ; textes : `{ id: texte | [recto, verso] }` (vide si identique à la carte d'origine).
- **Id = numéro imprimé en minuscules** : `bt22-083`, versions à part `bt22-009_spr` (Special Rare, autre illustration), `bt22-140_gdr` (God Rare), `bt22-054_pr` / `_pr02` (promos), promos `p-001`, decks `sd23-01`, coffrets `ex21-05`. `localId` « 083 », « 009 SPR ». Séries = préfixe du numéro : BT1…BT31 (noms des pages : « Z05 Booster -CRITICAL BLOW- » → « Critical Blow »), TB1-3, DB1-3 (Draft Box), EB1, SD1-23 (« Deck de démarrage … »), XD1-3, EX01…EX25 (coffrets, noms TCGplayer), P (promos) ; `NAMES` corrige les noms mal écrits. `max` = plus grand numéro sans version (BT22 = 140).
- Raretés : C, UC, R, SR, SPR, SCR, GDR, SLR, ST, EX, PR, CR, DBR, DR… (`RAR`). Normale / brillante : d'après TCGplayer (`vf`) ; inconnu → C / UC / R les deux, le reste brillant.
- **Prix** : `outils/ci/prix-dragonball.mjs` (TCGplayer catégorie 27 « Dragon Ball Super CCG » ; Fusion World = 80) → `_site/data/db-prix.json` (`.gitignore`), ~11 500 prix ; relié par le numéro « BT22-009 » + genre du produit (« (SPR) », « (GDR) », groupe Pre-Release / Promotion → PR). Dates des séries : groupe TCGplayer (« DBS-B01 » = BT1, « BT22 », « DBS-TB01 », « EB-01 », « DBS-BE04 » = EX04).
- Visuel de série : sachet TCGplayer `pk`, `PACKS_CROP` mesuré (pixels non blancs) quand le sachet ne remplit pas l'image.

## Reconnaissance
- Code **en bas à droite** : « BT22-083 R » (rareté après le numéro), « BT22-009 SPR », « SD23-01 ST », « P-001 PR ». `codesIn` : préfixes connus (BT TB DB SD XD EB EX, lus « 8T », « 87 », « B7 »…), chiffres mal lus ; P- seulement suivi de PR ; rien sur « 25/165 » ni « OP09-004 ». Rareté lue = celle de la carte → poids 1. Numéro sans « SPR » : ses versions (même numéro) sont ajoutées derrière, et **le code seul ne rend pas sûre** une carte qui a une version (`hasSib`) : l'image tranche.
- Extra Z couchée : `turned` (photo tournée vers la gauche), `T_BANDS` ; dans la base d'images, l'image tournée.
- **Leaders** : la base d'images a aussi le verso (`bt22-031#b`, `fromIds` rend la carte avec l'image du verso) ; le nom du verso est dans `names`.
- Brillant : pas mesuré (`foil` = null, comme Star Wars) → « Ta carte brille ? ».
- `detectGame` / `textScores` : code ≥ 0,85 (×3), « B.S./S., T.A. », PUISSANCE, Combat Z / Extra Z / Unisson, Éveil / Activation : Principale, mots-clés (Déflexion, Barrière, Bloqueur, Double Frappe…), Saiyan / Son Goku…, deck Z / Dispersion ; `recognizer-text › OTHER` : codes BT/TB/DB/SD/XD/EB, « Combat Z », « Activation : Principale ».
- Dos / certification : pas fait (pas de photo du dos).

## Mesures (photos d'Arnaud, banc `_tests-scanner/db-bench.js` : `__dbPage('16')`, `__dbSpy()`, `__dbAuto('dragonball/16.jpg')`)
- Page 16 sans base d'images : 8/9 sûres et justes en 47 s (Rayon diabolique couchée lue tournée ; le leader au verso BT22-031 lu « 8722-031 UO » → ajouté).
- **Avec la base d'images** (`data/db-index`, 7 748 images = 7 245 cartes + 503 versos de leaders, `DB_INDEX_V = 1`, 3,4 Mo) : page 16 **9/9 sûres et justes** (1er passage 138 s avec les chargements, ensuite **20 s**, ~1 s par carte) ; page 01 **8/8 sûres**, le dos Star Wars « Non reconnue » (148 s au 1er passage) ; « Toutes » : 9/9 justes (8 sûres, le verso du leader à vérifier — c'était avant la base d'images), ~3 min (licence cherchée carte par carte au 1er passage).
- Carte seule (Trunks découpée dans la photo 16) : sûre en 1,3 s en Dragon Ball, en « Toutes », et **depuis le mode Pokémon en 6 s** (bascule). Avant le correctif de `scan-single` (v3.68 : une licence qui propose une carte sans l'avoir lue ni reconnue ne l'emporte plus d'office), le mode Pokémon passait en One Piece (« Broggy »).
- Base d'images construite depuis les images téléchargées sur le PC (scratchpad `dbimg/`, petit serveur `save-server.mjs` : `/__dbimg/`, `/__tool/db-index-build.js` → `__dbIdx.build()` puis `__opIndex.pack(128, 'dragonball')`) ; **deux téléchargements en même temps sur le même fichier = 267 images abîmées** (repérées au calcul : « image illisible », refaites). Cartes couchées : toutes les Extra Z + `LAND` (4 Extras), mesuré sur les 7 245 visuels (marges blanches).
