# Star Wars: Unlimited (v3.67, `js/games/starwars.js`, 8ᵉ licence, Fantasy Flight Games)
Même logique que Final Fantasy et Wankul (voir `finalfantasy.md`, `wankul.md`) ; ici seulement ce qui diffère. Id de licence `starwars`, préfixe `sw`. Arnaud a des cartes françaises d'Étincelle de Rébellion (photos `_tests-scanner/18.jpg` = page 3 × 3 SOR 017…131 (rangées du haut et du bas coupées par le bord de la photo), `19.jpg` = page SOR 141…252 + 2 cartes Pokémon + Inferno Quatre Hyperspace 297, `20.jpg` = Inferno Quatre 297 Hyperspace brillante seule ; bonnes réponses dans `reponses.txt` ; copies dans `_tests-scanner/starwars/`). Pas encore de photo du dos.

## Données
- **Base officielle** : `GET https://admin.starwarsunlimited.com/api/card-list?locale=fr&pagination[page]=N&pagination[pageSize]=100` (Strapi ; **pas de CORS** ; 10 233 fiches en oct. 2026, 103 pages, ~2 Mo chacune, ~8 s par page ; `pageSize` 500 → 502) : une fiche par impression (Standard, Standard Foil, Hyperspace, Hyperspace Foil, Showcase, Standard / Foil / Serialized Prestige, Weekly Play, promos de tournoi SS/PQ/RQ/SQ/GC…), `variantOf` = fiche Standard, `reprintOf`, `expansion.code` (SOR, SHD, TWI, JTL, LOF, SEC, LAW, ASH, HMW, IBH, TS26, P25…), `rarity.character` (C U R L S), `type.value` (Unit Event Upgrade Leader Base Token), aspects / traits / arenas en français, `text`, `deployBox`, `epicAction`, `artFront` (300 × 419, ou 419 × 300 pour leaders et bases : `artFrontHorizontal`), `artBack` (face unité d'un leader), `localizations` (anglais, espagnol…). Certaines fiches « fr » sont restées en anglais (promos).
- **Visuels** `cdn.starwarsunlimited.com` : CORS `*`, lus directement. **Attention : beaucoup de chemins commencent par « / » (« https://cdn.starwarsunlimited.com//04010009_FR_… ») et ce « / » fait partie du nom : sans lui, 403** (6 134 visuels sur 6 362 refusés au premier essai). Leaders et bases (couchés) : relayés par `images.weserv.nl` avec `&ro=270` (sens du classeur d'Arnaud : le haut de la carte à gauche, vérifié photo 18).
- `outils/ci/starwars-cartes.mjs` → `data/sw-cartes.json` (**dans le dépôt**, 2,4 Mo, 6 362 cartes, 35 séries), chaque lundi par `index.yml` (étape « Liste des cartes Star Wars Unlimited », `cartes_sw`). Cache `sw1:index`. Format : `id, s, l, n (titre), st (sous-titre), ne / se (anglais), t (un ev up le ba to), a (affinités vi co ag ru he in), tr (traits), ar (te / sp), co, p, hp, x (texte + « Déployé : » + action épique ; vide si identique à la carte d'origine), r, img, h (couchée), v (version), vf (absent = normale + brillante, « n » normale seule, « h » brillante seule), fn (numéros des brillantes), tp / tpf (produits TCGplayer normal / brillant), b (carte d'origine)`.
- **Une carte = une illustration imprimée** : Standard + Standard Foil = une carte (variantes normale / brillante) ; Hyperspace (+ Foil), Showcase, Prestige, Prestige numérotée = cartes à part (`v`, numéros > total de la série : « 297 » pour 252 cartes → `isOfficial` = numéro ≤ `max`). **Depuis Passage en Vitesse Lumière (JTL), la brillante a son propre numéro** (Boba Fett 189 → 687) : gardé dans `fn`, reconnu par `byCode` / `codesIn` (→ la carte, brillante sûre).
- Séries : extensions (`main`, `max` = total imprimé), decks (`IBH` Bataille d'Intro : Hoth, `TS26` Twin Suns, `JET` = tous les jetons, id « jet-sor1 »), promos : `SORP`/`SHDP`/`TWIP` (Weekly Play rangées dans l'extension par la base, + Hyperspace « 5/20 »), `JTLP`… (extensions Weekly Play de la base), `P24` (promos de tournoi et d'avant-première d'Étincelle / Ombres / Crépuscule, id « p24-sor2b »), `SECX` (Carbonite de Secrets du Pouvoir), `P25`, `P26`, `J24`, `C24`, `CST`, `MV26`, `GG`… Dates : TCGplayer (`publishedOn`), sinon série d'origine, année du code, 1ʳᵉ mise en ligne.
- **Id = série + numéro** : `sor-038`, `sor-297`, `jtlp-001` ; deux cartes au même numéro → suffixe `b`, `c`… (`p24-sor2b`).
- Raretés : C Commune, U Peu commune, R Rare, S Spéciale, L Légendaire.
- **Prix** : `outils/ci/prix-starwars.mjs` (TCGplayer catégorie 79) → `_site/data/sw-prix.json` (`.gitignore`), 9 030 prix ; relié par `tp` (série = abréviation du groupe, « SOR-WPP » / « LOFWPP » → « SORP » / « LOFP », numéro « 031/252 » / « 297 ») ; brillante numérotée à part : `tpf`.
- **Visuel de série** : sachet TCGplayer `pk` (« … - Booster Pack », pas Carbonite), `PACKS_CROP` mesuré (SOR, JTL, TWI : image entière) ; `IC27` : pas encore d'image (`NO_PACK`). `logoText` = code de la série.

## Reconnaissance
- Code **en bas à droite** : « SOR • FR • 038/252 » (série, langue, symbole de rareté, numéro / total), Hyperspace « SOR • FR • 297 » (sans total, et un peu plus haut : cadre plus épais, ~0,92 de la hauteur). `codesIn` exige la langue (rien sur « 025/165 », « OGN · 013/298 ») ; total = celui de la série → poids 1, numéro > total sans total → 0,9 ; lectures vues : « SOR+FR 297 », « SOR-FRU 257 », « SOR-FR (À 166/252 », « S0R » ; « SOR-FR » et « 166/252 » sur deux lignes → `joinedLines` les recolle. Leaders et bases couchés : photo tournée d'un quart de tour (`turned`, comme les terrains Wankul), `T_BANDS`.
- Vérification par l'image : `data/sw-index` (6 362 cartes, `SW_INDEX_V = 1`, 3 Mo), construit dans le navigateur directement depuis le CDN (CORS ; les 741 couchées par le relais) en ~5 min, `labo-index-op.js` (`FILE.starwars`), petit serveur de travail Node avec `POST /__save` (scratchpad `save-server.mjs`).
- **Normale ou Hyperspace (`pickArt`)** : même illustration, et l'image préfère TOUJOURS la version Hyperspace (l'illustration va jusqu'au bord, plus de points communs : 100 contre 79, 152 contre 115 sur des cartes normales). Le numéro tranche (relu sur la carte recadrée avant de conclure) ; numéro illisible → **la normale devant, « à vérifier »**, la Hyperspace juste derrière. Essayé et abandonné : bandes des côtés comparées aux visuels (fausses sur les cases mal cadrées). `twinsOf` = même illustration ET même genre (Hyperspace avec Hyperspace).
- **Brillant : pas mesuré** (pas de `foil` exporté) : `foilMeasure` donne 0,8 sur la Hyperspace brillante d'Arnaud (visuels officiels de 300 px) → « Ta carte brille ? » ; sûr seulement si le numéro d'une brillante (JTL et après) est lu.
- `findCrop` : quand le nom est déjà lu, la découpe n'est gardée que si elle fait lire le code ; en classeur, la case seule (sinon le code d'une voisine : une carte Pokémon prise pour Ravitaillement).
- `detectGame` / `textScores` : code ≥ 0,9, Star Wars, LFL / FFG, « XXX • FR », unité terrestre / spatiale, action épique / déployez, mots-clés (Embuscade, Sentinelle, Raid N, Protégée…), factions ; `recognizer-text › OTHER` : codes SOR…HMW + FR, unité terrestre / spatiale, action épique.
- **Dos / certification : pas fait** (aucune photo du dos) : `backScoreOf(…, 'starwars')` retombe sur le modèle Pokémon, le classeur lit les cases quand même.
