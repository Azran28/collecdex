## Données
- **Base officielle de Square Enix** : `POST https://fftcg.square-enix-games.com/en/get-cards` (JSON `{ language: 'fr', text: '', type: [], … }`, 13 Mo, **pas de CORS**) : 4 261 cartes, noms / types / jobs / textes en 6 langues (`name_fr`, `type_fr`, `job_fr`, `text_fr`), élément en japonais (`火` Feu…), `category_1/2` (« VII », « DFF · X » écrit `&middot;`), visuels `images.full` (`fftcg.cdn.sewest.net/images/cards/full/<code>_fr.jpg`, 429 × 600, **carte entière, coins arrondis** ; `_fr_FL.jpg` = **version Full Art** (texte posé sur l’illustration, pas de cadre ; 593 cartes, Legacy Collection comprise) → carte à part `16-001fa`, `localId` « 001 FA » (en plus de la série : `isOfficial` = 3 chiffres), nom « Vaan (Full Art) », produit TCGplayer « (Full Art) » ; `thumbs/` 179 × 250). Textes : `[[br]]`, `[[s]]…[[/]]`, `《S》`, `《火》`, `《ダル》` (dull) → `cleanText` les rend lisibles (« (S) », « (Feu) », « (Dull) »).
- Complétée par **TCGplayer** (tcgcsv.com, catégorie 24) : dates des séries (`publishedOn`), n° de produit `tp` (relié par le code imprimé, `extendedData.Number`), et **les promos** (« FF: Promo Cards », 243 produits, 200 avec un numéro « PR-112/16-067L » ; la base officielle n'en a que 3) : nom / texte français pris sur la carte d'origine (`b`), image TCGplayer (`img: 'tcg:<produit>'`, anglaise ; 2 images refusées 403 : pr-123, pr-128).
- `outils/ci/finalfantasy-cartes.mjs` → `data/ff-cartes.json` (**dans le dépôt**, 2,2 Mo, 5 050 cartes dont 593 versions Full Art), chaque lundi par `index.yml` (étape « Liste des cartes Final Fantasy », `cartes_ff`). Cache `ff1:index`. Format : `id, s, l, c (code imprimé), n, ne, t (av so in mo cr), j (job), ca (catégorie), e (éléments fe gl ve te fo ea lu tn), co, p (force), r, x, img, ex (EX BURST), mc (multi-cartes), tp, b (carte d'origine), pe (genre de promo)`.
- **Id = code imprimé sans la rareté, en minuscules** : `16-006` (16-006C), `re-006` (Legacy Collection « Re-006C/16-003C »), `pr-112` (« PR-112/16-067L »), `c-004` (cristal, même `C-001` dans deux séries : gardé une fois), `b-001` (Boss Deck). `localId` = « 006 ». Séries : `1`…`29` (noms anglais : « Opus I »… « Emissaries of Light »), `Re`, `PR`, `C` (« Cristaux »), `B` ; groupes `ff-main / ff-extra / ff-deck / ff-promo` ; `logoText` « Opus XIV », « Série 16 », « Promos ». Pas de visuel de série (piste : sachets TCGplayer, `PACKS_CROP` comme Lorcana).
- **Visuel de série (v3.45)** : sachet de booster TCGplayer, n° de produit `pk` posé par le robot (`packOf` : produit « … Booster Pack » du groupe), recadré par `PACKS_CROP` de l’adaptateur (zone non blanche de l’image `_400w`, mesurée dans le navigateur) ; Opus XI (sachet 403) et Crystal Dominion (image provisoire « Opus XV ») = boîte de boosters ; Legacy Collection : aucune image (403) → `NO_PACK`, nom. - Raretés (lettre du code) : C Commune, R Rare, H Héros, L Légende, S Starter, B Boss, PR Promo, Cr Cristal. Brillant : toutes les cartes de booster existent en foil (`{ normal, holo }`, « Normale » par défaut) ; promos et cristaux = brillants.
- **Images** : sewest sans CORS → relais `images.weserv.nl` (`&w=360` / sans `w` en grand) ; promos : `tcgplayer-cdn` (CORS `*` ; CSP `connect-src` ajoutée), `_400w` / `_in_1000x1000`.
- **Prix** : `outils/ci/prix-finalfantasy.mjs` (copie de `prix-lorcana.mjs`, catégorie 24) → `_site/data/ff-prix.json` (`.gitignore`), 5 608 prix ; relié par `tp` (4 cartes sans produit).

## Reconnaissance
- Code **en bas, au milieu**, au bout de la dernière ligne du copyright (petites lettres noires, ou blanches sur les cartes sombres) : « 16-006C », « PR-112/16-067L », « Re-006C/16-003C », « C-004 ». `codesIn` : `série|numéro`, lettres mal lues (`ALT`), lettre de rareté après = poids 1 (sinon 0,75) ; **promo / réimpression avant la carte d'origine** (« PR-… » ×1,2, code écrit après une barre ×0,5) ; rien sur « 025/165 », « OP09-004 », « © 2015-2021 ». Zones `CODE_ZONES` / `OCR_BANDS` (0,925…0,995 × 0,2…0,8), nom en haut (`NAME_ZONES`).
- Vérification par l’image : `data/ff-index` (5 048 cartes, `FF_INDEX_V = 2`), construit depuis les petites images téléchargées une fois sur le PC (`_tests-scanner/ff-img/` du dossier de travail, `<id>.jpg`, pas par le relais ; `img.card` remplacé le temps du calcul), `twinsOf` = carte d’origine + réimpressions Legacy + version Full Art du même code.
- `detectGame` / `textScores` : code ≥ 0,9, SQUARE ENIX, CHARACTER DESIGN / Nomura, Break Zone, EX BURST, « 1 Avant », Soutien, dull, Final Fantasy, « Infligez » ; `recognizer-text › OTHER` : square enix, break zone, ex burst, final fantasy, code « 16-006C ».
- **Dos / certification** (`recognizer-image › ffBackScore`) : carte noire mate, logo argenté au milieu. Sous pochette brillante le noir devient gris → la couleur sombre ne suffit pas (des faces sont sombres et peu colorées) : presque rien de coloré (`sat` ≤ 0,03) et le détail concentré dans la bande du logo (`ratio` = détail de la bande 0,38…0,62 ÷ détail du haut et du bas ≥ 2,4, `band` ≥ 35). Dos des photos 3, 4, 9, 10 : 0,71–0,87 ; 21 faces des photos ≤ 0,14 ; dos Lorcana / Yu-Gi-Oh! ≤ 0,14. En classeur, dos sûr comme Pokémon (`scan-batch-list › recogOne`). `certify.js › backOf` l'inclut.

## v3.44 — cadrage et brillant (Arnaud : « le cadrage est pas bon… tu ne reconnais pas les effets de brillance », Chocobo 16-054 brillant au téléphone, captures `13.webp` / `14.webp`)
- **Mesure du cadrage** sur ses traits jaunes (`12.webp` = page 1) : `ff-bench.js › __ffTruthBoxes('12', __FF_BOXES_12)` (traits cherchés depuis l'intérieur de chaque case : la projection de `__ygTruth` prenait les traits des voisines) et `__ffPage1Err()` (coins retenus, pire coin en % de la diagonale ; « P » = recadrée par la page). Avant : 7 cartes à 1,1–2,2 %, **Ace 5,5 %** et **Valseur 2 8 %** (coins par l'illustration de travers : cartes sombres, proportions vraies 1,58). Le rognage du fond sombre des visuels (`visual-worker › trimBackground`) n'y était pour rien (essayé, annulé).
- `cardShaped` (adaptateur) : coins par l'image refusés si la forme, perspective retirée (`R.trueRatio`), n'est pas 88/63 ± 0,1 → la photo garde son détourage. `scan-batch-realign › refitSure` (Final Fantasy seulement) : carte sûre dont les coins s'écartent de ≥ 6 % de sa place dans la page → recadrée sur cette place. Après : Ace 2,6 %, Valseur 2 entière, les 7 autres inchangées. `snapQuad` / `findCard(…, { expect })` essayés : pires (5–10 %).
- **Brillant** : `foil(blob, card)` (exporté par l'adaptateur) = paillettes contre le visuel officiel non brillant (voir l'en-tête de la fonction) ; mesuré à la lecture (`top.foil`), affiché en carte seule (« ✨ Brillante (paillettes vues sur ta photo) »), dans le classeur par le sélecteur de version (`scan-batch-list › measureVers` : `ad.foil` pour une autre licence que Pokémon), enregistré par `addScanned` (`c.foil`). Carte seule ≥ 600 px : normales 1,9–2,3 (Molosse, Serah), brillantes 3,3–6,4 (Poussin chocobo, Chocobo de la capture, cristal) → sûre. Classeur (~400 px) : « lap » ≥ 0,44 → 4 brillantes sur 5 (Lightning, Chocobo, Lulu, Tidus ; Hyoh non), 0 normale sur 9 prise à tort, toujours « à vérifier ».
