# Yu-Gi-Oh! (v3.26, `js/games/yugioh.js`, 5ᵉ licence)
Même logique que Lorcana (voir `lorcana.md`) ; ici seulement ce qui diffère. Arnaud a des cartes françaises (photos `_tests-scanner/yugioh/`, 17 oct.).

## Données
- **YGOPRODeck** (`db.ygoprodeck.com/api/v7/cardinfo.php`, CORS `*`, 25 Mo ; `?language=fr` = noms et textes français pour ~11 700 cartes ; `cardsets.php` = séries) → `outils/ci/yugioh-cartes.mjs` fait `data/yg-cartes.json` (**dans le dépôt**, 2,4 Mo : 14 106 cartes, 42 926 impressions, 1 031 séries), relancé chaque lundi par `index.yml` (étape « Liste des cartes Yu-Gi-Oh! », `cartes_yg`). Cache `yg1:index`. **Textes pas gardés** (trop lourds) : la fiche les demande à l'API (`textOf`, cache `yg1:txt:<passcode>` 30 jours ; CSP `connect-src db.ygoprodeck.com`).
- Format : `cards` = tableaux `[passcode, nom FR (sinon anglais), nom anglais si différent, genre (frameType court), attribut, niveau/rang/lien, ATK, DEF (-1 = « ? »), type (anglais), autres illustrations (liste de passcodes) ou 0, sans nom français]` (`K` dans l'adaptateur) ; `sets` = `{ id, name, date, g (famille), img }` ; `p` = `{ série: [[id, n° de carte, rareté]] }` ; `a` = alias.
- **Id d'une impression = code imprimé sans la langue** (`codeKey`) : `RGBT-FR007` → `RGBT-007` ; `NECH-ENS10` → `NECH-S10` ; anciennes cartes européennes `LOB-F003` → `LOB-E003` (numérotées autrement que l'américaine `LOB-005` : la série LOB ne garde que l'européenne, le code américain devient un alias `a`, sauf s'il existe ailleurs, ex. réédition 25ᵉ anniversaire) ; **autre rareté du même code** : `RA04-087_scr` (la plus courante sans suffixe, ordre `RANK`) ; même code et même rareté dans deux séries : `…@<série>`. `localId` = « 007 », « 087 ScR » ; `isOfficial` = sans espace (raretés en plus).
- **Séries** : id = code (`RGBT`) ; code partagé par plusieurs noms (Special Edition, Sneak Peek…) : la plus grosse garde le code, les autres `ABPF.2`, `ABPF.3` (par date). Familles `groupOf` (noms anglais, regex) : Boosters, Decks, Collections et rééditions, Tins, Speed Duel, Éditions spéciales, Promos et tournois ; **ordre forcé** par `group.order` (sinon les promos, les plus récentes, passaient devant ; `sets.js` trie les familles par `order`). « Sans les promos » = `yg-promo`. Noms de séries en anglais (Konami garde surtout l'anglais ; les vieux noms français ne sont pas dans les données).
- Raretés : `RAR` (≈ 35 : Commune, Rare, Super Rare, Ultra Rare, Secret Rare, Ultimate, Ghost, Starlight, Quarter Century…) ; brillant = rareté ≥ Super Rare (`holoRar`). 1ʳᵉ édition / illimitée : pas encore distinguées.
- **Images** : `images.ygoprodeck.com/images/cards/<passcode>.jpg` (cartes anglaises, 813 × 1185 ; pas de CORS) → relais `images.weserv.nl`. **Le relais limite (~2 500 images / quart d'heure par adresse)** : ne jamais construire l'index par lui (10 703 échecs la 1ʳᵉ fois) → images `cards_small` téléchargées une fois sur le PC (YGOPRODeck demande de ne pas les appeler en masse), servies en local pour le calcul. Visuel de série : `images/sets/<code>.jpg` (sachet / boîte) relayé, sauf ids `X.2`.
- **Prix** : `outils/ci/prix-yugioh.mjs` (robot de mise en ligne, chaque matin) → `_site/data/yg-prix.json` `{ m, p: { 'RGBT-007|c': $ TCGplayer de l'impression }, c: { passcode: € Cardmarket de la carte (la moins chère des impressions) } }` (`.gitignore`) ; `price()` = impression si connue (USD), sinon Cardmarket (EUR). 14 142 cartes, 12 207 impressions.
- Défauts connus des données : quelques noms français restés en anglais chez YGOPRODeck (« Dark Magician », « Red-Eyes Black Dragon », « Monster Reborn ») ; une carte à plusieurs illustrations a pour passcode principal celui de YGOPRODeck (Dragon Ultime aux Yeux Bleus : 23995348, dessin récent).

## Reconnaissance
- Code **sous l'illustration à droite** (« RGBT-FR007 », petite police à empattements, mal lue par Tesseract : « RGB T-FROO7 », « CRMSTROGI ») et **passcode** 8 chiffres en bas à gauche. `codesIn` : préfixe connu (O/0, 1/I), langue sur 2 lettres (ou mal lue, poids 0,6), `F003` européen, chiffres mal lus (`DIG`, « / » = 7), lignes aussi sans espaces ; rien sur « 25/165 » ni « OP09-004 » (pas de langue).
- **Zones à l'échelle de la photo** (`scaleFor` : lettres ~40 px ; ×4 sur une photo de 2 000 px = rien de lisible) et **bandes fines qui glissent** (0,695…0,795 ; une bande de 6 % prenait le cadre de l'illustration). Carte recadrée par l'image : `CROP_ZONES` (3 réglages × 4 bandes).
- **L'image désigne la carte, le code l'impression** : index `data/yg-index` = **une entrée par illustration** (`#<passcode>`, 14 103 + 156 autres illustrations = 14 259, 5 Mo, `YG_INDEX_V`), `cardsOfIndex` → impression de la série de la page ou la plus courante (`baseFirst`), autre illustration = son image (`artId`) ; `printsOf` = toutes les impressions (même score) ; **`choosePrint`** compare le code de chaque impression (« RGBT-FR007 », « LC5D-FR088 »…) à tout ce qui a été lu (`printScores`, O = 0…, fenêtre glissante) : ≥ 0,75 avec 0,12 d'avance, ou ≥ 0,65 avec 0,25 d'avance → en tête, « sûre » si l'image est nette et une seule rareté pour ce code.
- Carte détourée trop court (bas sombre confondu avec la main) : coins par l'image hors de la découpe → vrais bords cherchés sur la photo d'origine (`original` / `context`, `V.quadOn`) puis relecture du code.
- **Mesures (photos d'Arnaud, banc `_tests-scanner/yg-bench.js` : `__ygReal(fichier)`, `__ygPage(fichier, 'classeur', 'yugioh', rot)`, `__ygBack(marge)`)** : 5 cartes seules (Rose Tentaculaire ×2, La Moitié ou Rien, Dragon Ultime aux Yeux Bleus ×2) : **5/5 bonne carte, 3 sûres avec la bonne impression** (code lu), 1–2 s ; « Toutes » : licence reconnue ; mode Pokémon : bascule (mots des faces ajoutés à `recognizer-text › OTHER` : KAZUKI TAKAHASHI, ATK/, Carte Magie/Piège, code « -FR007 » — « KONAMI » n'est que sur le dos). Pages : **photos d'Arnaud prises classeur tourné (cartes couchées dans une photo en largeur) → la grille 3 × 3 cherche des cartes droites : 2/9** ; même photo tournée droite : page 2 (TDGS/CRMS) 9/9 bonne carte (4 sûres), page 1 (FR, EN, JP) 7/9 (Loup de la Peste non lu, carte japonaise « Naga » prise pour une autre), ~60 s ; page de 9 dos : 9/9 ignorés.
- **Cadrage (v3.27, traits jaunes d’Arnaud : `_tests-scanner/yugioh/page3-traits.webp` = page de 9 vieilles cartes FR, `koaki-traits.webp` = carte seule ; vérité lue par `yg-bench.js › __ygTruth`, alignée sur la photo pour la carte seule)** : coins par l’image (ORB, illustration seule) prolongés en homographie = 4,6 % de la diagonale en moyenne (dedans : images YGOPRODeck un peu serrées + perspective amplifiée) ; détecteur de cartes du classeur (`detectCards`) 5–15 % (s’arrête au cadre intérieur) ; `snapQuad` / `findCard` guidés 5 % ; bords recalés côté par côté (bordure sombre fine, `__ygRefine`) : pas mieux. Retenu : **`fullQuad`** = transformation affine ajustée sur la zone de l’illustration (`ART_GRID`), vrais bords `OUTER` dans ce repère → **1,9 % en moyenne, pire 3,3 %** (validation croisée sur 10 cartes) ; dans le déroulé complet : page 8/9 cartes ≤ 2 % (Grès 4,8 %, cartes empilées dans la pochette), carte seule 1,9 % ; `cropQuad` (coins ramenés au bord si la carte dépasse de < 6 %). Code relu sur la carte entière : vers 0,72 de la hauteur (`CROP_ZONES` 0,69…0,775). Codes européens « SDJ-F006 » = aussi « SDJ-006 ».
- **v3.28 (photo d’Arnaud au téléphone, Dragon Ultime aux Yeux Bleus JMP-EN005 tenu en main, `beud.webp` + traits `beud-traits.webp`, capture d’écran `beud-ecran.webp`)** : le détourage de la caméra coupait la carte (trop serré) → rien de net à l’image sur la découpe ; les alentours la trouvaient (41) mais `visualPass` ne gardait ce résultat que « sûr », jamais le cas d’une carte aux impressions de même dessin → « Je n’ai pas reconnu la carte ». Maintenant gardé dès que l’image y est nette (`expand` = toutes les impressions), photo recoupée sur les vrais bords (1,4 % des traits) ; « IMPENOOS » lu = JMP-EN005 (`canon` : J = I = 1) → JMP-005 en tête (2 raretés : à choisir).
- **Dos / certification** (`recognizer-image › ygBackScore`) : le modèle 24 × 33 ne marche pas (filets du tourbillon jamais au même endroit : 0,07–0,25) → part cuivrée de la bordure (`bord` ≥ 0,35), bande juste à l'intérieur sombre (`bord − in2` ≥ 0,15 : sur une face, le cadre orange est large — « Dragon Fantôme »), pas de couleurs froides au centre (`cool` ≤ 0,08), pas de zone de texte claire (`tb` ≤ 0,3) ; 5 cadrages × 5 décalages. Dos 0,63–0,87 (11/11 occidentaux, 10/11 avec 15 % de marge), 23 faces ≤ 0,24. Dos japonais (OCG) : pas reconnu. `certify.js › backOf` l'inclut. Test : `tests/dos-yugioh.jpg`.

## Ailleurs
- Import : `importer.js › matchYG` (code complet avec la langue « RGBT-EN007 », rareté de la ligne, sinon nom FR/EN + série) ; catégorie « YuGiOh » / « Yu-Gi-Oh! ».
- Combats : `battle.fighterYG` (monstres seulement, pas les jetons ; PV = 30 + DEF ÷ 40 + niveau × 5, attaque = ATK ÷ 30, coût 1–3 selon le niveau, « Position de défense » si DEF > ATK, Extra Deck = 1 énergie au départ, « ? » = 4000), `YG_ATTR` attribut → type, `LEVELS_YG` (Duelliste débutant → Pharaon : dieux égyptiens, Dragon Ultime), `battleCards.effectOfYG` (cartes célèbres par nom `YG_BY_NAME`, sinon texte FR et genre : Terrain = stade, Équipement = +20 PV…), pas de carte d'énergie : **Pot de Cupidité** (+1 énergie) dans les decks de l'ordinateur et de prêt ; `LIC.yugioh` (Deck, « Duels au Royaume des Duellistes »), `say` (monstre), `YG_NAMES` ; décor `img/combat/arene-yugioh.svg`, dos `dos-yugioh.svg`, CSS `.g-yugioh` (Égypte : or, cuivre, nuit pourpre).
- Badges : `yg-exodia`, `yg-dragons`, `yg-dieux`, `yg-secret`. Icône `pyramid`. `friends.js` / `duel.js` acceptent `images.ygoprodeck.com/images/cards/<n>.jpg` (relayé en combat).
